# Финальная доводка и границы проверки

## Что изменено

- Размеры текста переведены из фиксированных px в rem. При увеличении базового
  шрифта до 150–200% меняются и заголовки, и подписи, а формы/карточки перестраиваются,
  вместо обрезания текста или принудительного уменьшения шрифта.
- Адаптивные колонки БЖУ, воды и форм, переносы длинных подписей, увеличенные
  элементы управления. Поля дат больше не задают минимальную ширину всей карточки.
  SVG-графики сохраняют собственную систему координат: эквивалентная таблица
  значений, средние и подписи снаружи графика масштабируются как обычный текст.
- На широком экране нативного APK скрываются маркетинговый блок и рамка телефона.
  Веб-макет остаётся лишь средством разработки, публичная веб-версия не добавлена.
- Навигация переводит фокус на заголовок нового экрана. Добавлен переход
  клавиатурой к основному содержимому, фокус остаётся внутри открытого диалога,
  Escape закрывает его с возвратом к кнопке открытия. Видимый фокус предусмотрен
  для ссылок, списков, текстовых полей и скрытого file input через обёртку.
- Ошибки форм объявляются как alert. Декоративные SVG остаются скрытыми от
  скринридера, элементы ввода и кнопки имеют подписи.
- Устранён конфликт color-scheme в принудительно светлой теме. Поддерживаются
  системная тема, уменьшение движения и режим принудительных контрастных цветов.

## Зависимости

Полный npm-аудит обнаружил замечания в dev-инструментах, в том числе критические
для старого Vitest/tinypool; production-аудит был чистым.

- Vitest 3.2.7 → 5.0.5; совместим с используемыми Node 24 и Vite 6.4.5.
- Добавлен @axe-core/playwright 4.14.0 как dev-зависимость для тестов WCAG.
- В текущем Capacitor CLI 8.5.3 остаётся xcode 3.x. Для него задан узкий override
  uuid 11.1.1: исправленная версия сохраняет CommonJS и v4 API. Отдельный smoke-test
  проверяет генерацию UUID через реальный xcode API. Не применялся audit fix --force
  или откат CLI, runtime-пакеты не обновлялись без необходимости.
- На момент итогового `npm audit` замечаний не осталось, включая dev-зависимости.
  Это проверка реестра npm, не гарантия отсутствия всех дефектов и не аудит Maven/AAR.
- При обновлении Capacitor CLI проверить, нужен ли override, и пересоздать отчёт.
  Runtime-инвентарь лицензий не изменился.

## Автоматическая матрица

Playwright `app/e2e/final-accessibility.spec.ts`:

- 320×568, 360×640, 390×844, 412×915 со стандартным текстом;
- 320×568 и 390×844 с текстом 200%; 640×360 с текстом 200%;
- 768×1024 с текстом 150%; нативная компоновка 740×360 и 800×1280;
- пять вкладок: Главная, Дневник, Наставник, Прогресс, Профиль;
- WCAG 2/2.1/2.2 A/AA через axe в светлой/тёмной теме;
- диалоги добавления, ручного ввода, каталога на коротком экране с крупным текстом;
- обход Tab/Shift+Tab, Escape, переход к содержимому, возврат фокуса;
- системная/принудительная тема, reduced-motion и forced-colors.

Также выполняется существующий набор основных сценариев: регистрация и цели,
ручная запись и распознавание на контролируемых ответах, изменение порции,
избранное/копирование, офлайн-каталог, наставник/отмена ответа, прогресс,
напоминания, CSV и JSON/откат восстановления. Проверки данных и формул — Vitest.
Платные запросы провайдеру не используются тестовым набором.

Команды:

```sh
npm ci
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e:local -- --workers=2
npm run test:e2e:built -- --workers=2
npm audit
```

Для native-сборки использовать существующий Android APK workflow и постоянные
GitHub Secrets подписи. Контрольный debug APK из тестовой среды нельзя ставить
как обновление поверх пользовательского signed APK: сертификаты разные.

## Что всё равно проверить на реальном Android

Автоматическая матрица — Chromium и CSS-масштабирование текста, **не физический
тест Android font scale/TalkBack на всех устройствах**. Перед окончательным выпуском:

1. На телефоне включить крупный шрифт и масштаб экрана; пройти профиль, дневник,
   редактирование блюда, CSV/JSON и работу экранной клавиатуры.
2. TalkBack: подписи, порядок чтения, фокус после смены вкладки и закрытия диалога.
3. Камера/галерея, отмена выбора и отказ в разрешении, сохранение файла в «Файлы».
4. Установить подписанный APK поверх предыдущего и убедиться в сохранности дневника.
5. Проверить офлайн-режим и возврат сети; распознавание и наставник с реальным
   AnyModel отдельно, так как автоматические сценарии используют mock-ответы.
6. Фоновую доставку уведомлений, перезагрузку и энергосбережение — по
   `docs/NOTIFICATIONS.md`. Браузерный тест не доказывает работу Android AlarmManager.

Нулевой результат axe не означает полного соответствия всем требованиям
доступности: ручная проверка скринридером и людьми остаётся необходимой.

## Итог контрольного прогона

- `format:check`, `lint`, `typecheck`, полная сборка — без ошибок.
- 250 Vitest-тестов и 5 Node-тестов — пройдены.
- 93 Playwright-сценария — пройдены отдельно на dev и built конфигурациях.
- `npm audit`: 0 известных уязвимостей во всех npm-зависимостях.
- Capacitor Android sync и `assembleDebug` — успешно. Gradle подтвердил актуальность
  результата 13 Java-тестов (`testDebugUnitTest`), без ошибок и пропусков.
- UI-тесты адаптивности не расходуют серверную квоту регистрации: используются
  тестовый токен и управляемый ответ распознавания. Проверки серверных лимитов
  остаются в серверных тестах; production-лимиты не ослаблялись.
- В тесте сохранения этикетки перезагрузка ждёт окончания IndexedDB-записи
  и закрытия диалога, а не прерывает незавершённое сохранение.
