# Проверка Android-приложения: локальный этап и приёмка на телефоне

## Статус

Локальные автоматические проверки завершены. **Приёмка на физическом Android ещё не завершена.** Камера, системная клавиатура, выбор приложения для экспорта и кнопка Android проверены только через адаптеры/моки и мобильный Chromium, не на устройстве. Эмулятор Android и полноценная Gradle-сборка в этой среде не запускались. APK нужно собрать штатным workflow Android APK в GitHub Actions.

Рабочий продукт остаётся только Android APK. Локальный браузер используется как тестовый стенд интерфейса, не как дополнительная веб-версия для пользователей. Секреты, ключ подписи, workflow релизов и серверные настройки этим изменением не заменяются.

## Что исправлено

- Новый выбор JSON сразу сбрасывает старое подтверждение импорта. Повреждённый или слишком большой файл не оставляет доступным импорт предыдущего файла. Отмена недоступна во время записи.
- Экспорт на Android сохраняется в отдельный уникальный файл приватного кеша. Файл больше не удаляется сразу после завершения системного Share: получатель может прочитать его позже. Очистка собственных JSON старше суток выполняется при следующем экспорте, не по таймеру. Для постоянной копии пользователь должен сохранить файл вне кеша приложения.
- Отмена камеры/галереи не считается ошибкой. Отказ разрешений и другие сбои показывают понятную ошибку вместо молчаливого закрытия.
- Повреждённое фото получает русское сообщение об ошибке и не отправляется на распознавание.
- Для числовых полей профиля, веса и компонентов указаны подходящие режимы клавиатуры. В Android включён adjustResize; для полей добавлены отступы прокрутки. Фактическое поведение конкретной клавиатуры требует проверки на телефоне.
- Ручная форма явно фокусирует название после открытия. После закрытия диалога фокус возвращается к кнопке добавления только после удаления модального слоя.
- Кнопка Android «Назад» сначала закрывает диалог/редактирование профиля, затем возвращает на Главную; на корневом экране остаётся системное поведение выхода. Адаптер покрыт unit-тестами, физическое поведение пока не подтверждено.

## Автоматическая проверка

- ESLint, TypeScript, сборка клиента и сервера: успешно.
- Vitest: **111 тестов**. Включая новые проверки камеры, кнопки «Назад» и времени жизни экспортируемого файла.
- Node: **4 проверки адреса API** и отдельно **7 проверок постоянной подписи/версии APK**.
- Playwright: **27 сценариев на dev-сборке + 27 на собранном клиенте** (локальный mock-сервер, без платных запросов AnyModel).
- Синхронизация ресурсов/плагинов Capacitor Android: успешно. Это не заменяет сборку и установку APK.

Новые E2E-сценарии: ручной дневник/вода/вес без сети; сохранение данных после перезагрузки с отключённым API; редактирование профиля без потери дневника; повреждённый JSON после корректного; отмена импорта; экспорт и восстановление еды/воды/веса в чистом хранилище; повреждённые фото; лимит и удаление фото; прокрутка/фокус при высоте экрана 360 px; миграция старой IndexedDB v1 в v3.

При проверке перезапуска в браузере оболочка загружается локально по HTTP, а API блокируется. Холодный запуск APK в авиарежиме этим тестом **не доказан**: он входит в приёмку ниже. Тест уменьшенной высоты окна **не заменяет** настоящую экранную клавиатуру Android.

## Приёмка на телефоне — выполнить владельцу

Сначала: в Профиле экспортировать JSON и убедиться, что он сохранился в Файлах/на другом устройстве. Старое приложение не удалять и данные Android не очищать.

1. **Обновление.** Actions → Android APK → Run workflow на main. API URL: `https://racionika.onrender.com`. После успеха скачать новый подписанный APK из черновика Releases и установить поверх текущего. Проверить прежний профиль, блюда, воду и вес.
2. **Профиль.** Изменить имя/вес/цель, сохранить, закрыть приложение и открыть снова. Проверить новую норму и сохранность старого дневника. Проверить дробный вес своей клавиатурой (точка/запятая).
3. **Камера и галерея.** Снять фото, выбрать существующее, отменить выбор. Отдельно проверить отказ разрешения и повторный вход после разрешения в Android. Проверить вертикальную/повёрнутую фотографию. Запрос к настоящему ИИ выполнять только с обычным фото еды без личных данных; это может расходовать баланс AnyModel.
4. **Клавиатура.** На экранах профиля, чата и добавления блюда открыть клавиатуру, прокрутить до последнего поля и кнопки сохранения. Проверить маленький экран и крупный системный шрифт. Кнопки не должны становиться недоступными.
5. **Назад.** Из открытого диалога нажать системную «Назад» (при открытой клавиатуре первое нажатие может закрыть её). Затем из Профиля/Дневника вернуться на Главную. Не должно происходить неожиданного выхода из диалога с потерей уже сохранённых записей.
6. **Офлайн.** В авиарежиме полностью закрыть и заново открыть APK. Внести ручное блюдо, воду и вес, ещё раз перезапустить. Все записи должны остаться. Для распознавания и чата интернет нужен; недоступность ИИ не должна блокировать ручной дневник.
7. **Экспорт/импорт.** Сохранить JSON через системное меню, открыть файл спустя минуту и убедиться, что он не пустой. Импортировать ту же копию: сначала проверить preview/отмену, затем подтвердить. Повторный импорт не должен создавать дубли с теми же ID. Проверить ошибочный JSON: данные должны остаться без изменений. Не удалять рабочие записи ради теста.

Для сообщения об ошибке: модель телефона, версия Android, версия приложения/номер сборки Actions, последовательность нажатий, ожидаемое и фактическое поведение, скриншот без ключей/паролей и личных данных. Проверки камеры/Share/клавиатуры/офлайн-запуска отмечать выполненными только после реального результата на телефоне.
