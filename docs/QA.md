# Проверки 0.2.0

2026-10-24, Linux sandbox, Node 24.22.1, системный Chromium через Playwright. Проверена техническая версия, не всё исходное ТЗ.

- format:check, lint (0 предупреждений), typecheck в трёх workspaces — успешно.
- npm test: **61 тест, 7 файлов** — успешно.
- npm run test:e2e:local: **11 браузерных сценариев** — успешно.
- npm run test:e2e:built: **11 сценариев на собранном сайте и API одного origin** — успешно.
- npm run build: shared, клиент и сервер — успешно.
- npm audit --omit=dev: **0 найденных уязвимостей** на момент проверки. Это не полный аудит безопасности.

## Покрытие

Unit/inject: арифметика порций и автодобавок, невозможная сумма БЖУ, локальные даты, Zod-контракты, JWT и подделка токена, версия приложения, код доступа, валидация до вызова провайдера, проверка JPEG-контейнера, дневные/IP/глобальные лимиты, сброс UTC, HTTP 429, обслуживание, ошибки без утечки секретов и ограниченный повтор неверного JSON.

Форматы AnyModel/Anthropic/OpenAI/Gemini проверены через подставной fetch. Платных запросов не было. AnyModel: проверены Chat Completions, Bearer, точный model ID, передача JPEG, usage, отказ при усечённом ответе и отсутствие выдуманной цены в USD. Публичная конфигурация требует код доступа. Загрузка сайта не расходует минутный API-лимит, сам API по-прежнему ограничен.

Браузерные сценарии:

1. Ручной резервный ввод, вода, перезагрузка.
2. Описание → деморазбор → правка граммов → пересчёт без нового запроса → сохранение, перезагрузка и редактирование.
3. Фото PNG → сжатый JPEG, явная маркировка демо.
4. Наставник и сохранение локальной истории.
5. Отсутствие согласия блокирует отправку; экран 360×640 без горизонтального переполнения.
6. Повтор описания использует кеш без нового вызова.
7. Lookup ингредиента и отключение автодобавок.
8. Понятная ошибка квоты, доступный ручной ввод.
9. Ответ «не еда» нельзя сохранить как блюдо.
10. Основная навигация.
11. Настольная рамка 1440×1000 без переполнения.

Визуально осмотрены мобильная главная, форма описания, ошибка согласия, верх/середина/низ разбора, сохранённое блюдо, наставник; фотоформа в тёмной теме на ширине 390 и 360 px; настольная рамка 1440 px. Найденное неоформленное поле наставника исправлено и повторно осмотрено. Длинный диалог прокручивается; перекрытия содержимого не обнаружены.

## Что не подтверждено

- Живые запросы ИИ, точность распознавания, масса и пищевые значения, доступ моделей аккаунту, реальный счёт. Ключей нет. Демо — не проверка распознавания.
- Android APK, подпись, установка и нативные Camera/Keystore/Notifications. SDK здесь отсутствует.
- Render deploy и полный GitHub Actions. Локальный прогон не заменяет удалённый CI.
- Нагрузочный тест, пентест, постоянные распределённые квоты, полная миграционная матрица Dexie и все требования исходного ТЗ.

Исходники 0.2.0 опубликованы на GitHub; дополнение AnyModel/Render подготовлено отдельным изменением. Удалённый CI проверяйте в Actions для конкретного коммита.

Собранная версия дополнительно осмотрена на ширине 390 px: главная и форма с адресом текущего сервера. Ошибок консоли, неудачных загрузок ресурсов и горизонтального переполнения не найдено. Закрытые пути /.env и /server/.env вернули 404. Сервис Render не создан, живой AnyModel не проверен.

## Android-only конфигурация

Render Blueprint переведён на API-only: SERVE_WEB=false, npm run build:server. Отдельная веб-публикация не требуется. Четыре Node-теста проверяют конфигурацию APK: корректный HTTPS URL, отсутствие адреса, HTTP/localhost, секреты/путь/параметры в URL. Ручной GitHub Actions workflow Android APK подготовлен, но не запускался; успешная Gradle-сборка, установка и нативные плагины не подтверждены.

API-only режим дополнительно проверен с фиктивной production-конфигурацией без запросов к ИИ: / → 404, /health → 200, /v1/config → provider:anymodel. Проверки формата, lint, typecheck, 61 Vitest-тест и 4 Node-теста конфигурации прошли. Сборка shared + server успешна. npm audit --omit=dev: 0; полный npm audit сообщил 9 проблем в dev-зависимостях (7 moderate, 2 critical, включая цепочку Vitest/tinypool). Обновление инструментов требует отдельной проверки совместимости; нулевых проблем во всех зависимостях не заявляем.

Сборка интерфейса с фиктивным HTTPS API URL и cap sync android прошли: обнаружены 10 Android-плагинов. Платных сетевых запросов не было. Это проверка подготовки Android-проекта, не Gradle assembleDebug и не проверка установки APK.

## Первый удалённый запуск APK: исправление SDK setup

По логу пользователя workflow остановился до npm/Gradle: setup-android@v3 вызвал sdkmanager tools и получил Failed to find package 'tools'. Причина — пакет tools в значении packages по умолчанию. Workflow теперь явно передаёт packages: platform-tools; SDK Platform 36 и Build Tools 36.0.0 устанавливаются следующим шагом. Подробный вывод текста лицензий отключён. Повторная удалённая сборка после исправления ещё не подтверждена.

## Автоматический черновик APK

Пользователь сообщил об успешной APK-сборке после исправления SDK. Добавлена отдельная задача draft-release с needs:apk, минимальным contents:write и загрузкой artifact racionika-debug-apk. Команда gh release create использует --draft и --target точного SHA; файл проверяется на непустоту. Проверены YAML-структура, синтаксис bash и команда с подставным gh без обращения к GitHub Releases. Реальное создание черновика требует следующего запуска Actions и пока не подтверждено. Старые artifacts автоматически не мигрируют.
