# Android APK + AnyModel: Render только для API

Целевой продукт — устанавливаемое Android-приложение (.apk), не сайт. Схема: **APK на телефоне → HTTPS API на Render → AnyModel**. Дневник/вода/чат хранятся локально на устройстве; ИИ требует интернета. Ключ AnyModel хранится только в Render Environment, никогда в APK.

## 1. Подготовить AnyModel

Получите API-ключ, проверьте баланс и выберите модель с поддержкой изображений (vision / imageToText, не генератор картинок). Скопируйте точный API ID вместе с префиксом провайдера, если он указан. Для первого теста можно использовать один ID в MODEL_FAST и MODEL_ACCURATE. Доступность и расход зависят от маршрута и аккаунта.

Документация: https://anymodel.org/api-docs.md . Ключ не присылайте в чат, не загружайте в GitHub и не вводите в поле адреса API.

## 2. Создать API на Render

1. Откройте https://dashboard.render.com/ → New → Blueprint.
2. Подключите GitHub, разрешите доступ к приватному inderdrag/racionika.
3. Выберите main и render.yaml.
4. Введите:

| Переменная       | Значение                           |
| ---------------- | ---------------------------------- |
| ANYMODEL_API_KEY | Ваш ключ AnyModel, только в Render |
| MODEL_FAST       | Точный API ID vision-модели        |
| MODEL_ACCURATE   | Для первого запуска тот же ID      |

JWT_SECRET Blueprint генерирует автоматически. AI_PROVIDER=anymodel, SERVE_WEB=false, NODE_ENV=production, MOCK_AI=false, REQUIRE_ACCESS_CODE=false уже заданы. Сервис называется racionika, но публикует **только API**, без веб-версии. Тип Render «Web Service» означает серверный процесс; это не требование делать пользовательский сайт. Отдельный Static Site не нужен.

5. Проверьте тариф (в файле Free) и дождитесь Live.
6. Скопируйте реальный HTTPS-адрес сервиса. Проверьте /health (status:ok) и /v1/config (mode:real, provider:anymodel). Эти проверки не подтверждают валидность ключа и доступ модели: это проверяется настоящим запросом из приложения. Корень / должен возвращать 404, это нормально — сайта нет.

### Если сервис уже создан

Не создавайте второй оплачиваемый сервис без необходимости. В существующем сервисе: Branch=main, Root Directory пустой, Runtime=Node; Build Command:

```sh
npm ci --include=dev && npm run build:server
```

Start Command:

```sh
npm run start -w @racionika/server
```

Health Check Path: /health. В Environment установите SERVE_WEB=false и остальные переменные из render.yaml. При ручной настройке JWT_SECRET — отдельная случайная строка минимум 32 символа. NODE_VERSION=24.22.1; PORT предоставляет Render. Сохраните с повторным deploy. Если была отдельно создана ненужная Static Site — она для APK не используется.

Blueprint autoDeployTrigger=checksPass: следующие автоматические deploy ждут CI. Проверьте GitHub Actions при задержке. Бесплатный сервер может просыпаться не сразу. Квоты пока в памяти одного процесса и сбрасываются при перезапуске; для публичного использования нужны постоянные счётчики и отдельный бюджет у AnyModel.

## 3. Получить тестовый APK без Android Studio

В репозитории подготовлен ручной workflow Android APK. Пользователь сообщил об успешной APK-сборке после исправления Android SDK. Новое автоматическое создание черновика релиза ещё требует проверки следующим запуском.

1. Откройте GitHub → inderdrag/racionika → Actions → Android APK.
2. Нажмите Run workflow, выберите main.
3. В api_base_url вставьте **только публичный HTTPS-адрес Render**: без /v1, /health и параметров. Это не секрет. Ключ AnyModel и код доступа сюда не вводите.
4. Запустите. Если GitHub требует включить Actions — включите для своего репозитория. В приватном репозитории действуют квоты/возможные расходы GitHub Actions.
5. После сборки задача Create draft release автоматически создаст новый **черновик** в GitHub → Releases и прикрепит app-release.apk. Откройте https://github.com/inderdrag/racionika/releases, найдите черновик «Рационика — Android APK #…» и скачайте APK напрямую, без ZIP. Публикации автоматически нет; Publish release нажимайте только если сами решите опубликовать релиз. Для доступа к черновикам войдите в GitHub под аккаунтом с правом записи в репозиторий.
6. Резервная копия остаётся в запуске → Artifacts → racionika-release-apk: скачайте ZIP, распакуйте, внутри app-release.apk. Сам ZIP на телефоне не устанавливается.
7. Если APK собрался, но Create draft release завершилась ошибкой, APK всё ещё доступен в Artifacts. Откройте лог сбойного шага; создание черновика требует contents:write у GITHUB_TOKEN. Новый workflow задаёт это право только задаче черновика, не задаче сборки.

Это release-подписанная сборка после однократной настройки ключа (docs/RELEASE.md), не публикация в магазине. Она собирает интерфейс внутрь APK через Capacitor; отдельный опубликованный сайт и браузер для запуска не нужны. Нативная работоспособность плагинов и установка на реальный телефон требуют проверки.

## 4. Установить на телефон

Передайте app-release.apk на Android-телефон, откройте файл и при необходимости разрешите установку из этого источника. Устанавливайте только сборку из своего репозитория. После установки откройте «Рационика» через значок приложения. При первом входе заполните локальный профиль и цель, проверьте расчёт, при желании включите ИИ одним явным согласием. Код доступа больше не вводится.

Добавить еду → описание с известной массой → Определить КБЖУ. Затем проверьте фото и наставника. Настоящие запросы расходуют баланс AnyModel. КБЖУ по фото — оценка, а не точное измерение скрытого масла, рецепта и массы.

При смене домена API потребуется пересобрать APK с новым адресом. Удаление приложения/очистка его данных удаляет локальный дневник. Для обновлений нужна совместимая подпись; подпись и стабильный выпуск release APK ещё не настроены. Не удаляйте приложение ради обновления без экспорта данных.

## Если ошибка

- Render не стартует: проверьте ключ, обе модели, JWT_SECRET, команды сборки/запуска и логи без секретов.
- / возвращает 404: это ожидаемо, открыт API, а не сайт.
- APK не собирается: откройте красный шаг Actions; пришлите ошибку без секретов. Подготовленный workflow не гарантирует успешную сборку до фактического запуска.
- «Адрес сервера не задан»: пересоберите APK с правильным api_base_url. localhost в APK — телефон, не ваш ПК и не Render.
- «ИИ временно недоступен»: баланс, активность ключа, точные API ID, поддержка Chat Completions и изображений выбранным маршрутом.
- Не отправляйте много повторов подряд во время пробуждения сервера: начатый запрос к ИИ мог оплачиваться.

Render пользователя https://racionika.onrender.com проверен по /health и /v1/config: сервер работает в режиме real/anymodel. Пользователь сообщил об успешной сборке APK; работу распознавания по фото пользователь также подтвердил. Это не независимая проверка точности или новой версии 0.3.0. Ключ, баланс и совместимая модель нужны для настоящего ИИ.

### После исправления workflow

Если первый запуск упал на setup-android с Failed to find package 'tools', исправление добавлено в main. Запустите **новый Run workflow** из ветки main с тем же адресом Render. Не используйте Re-run старого запуска: он повторяет workflow старого коммита. Повторное создание Render, смена ключа и модели не нужны.

## Обновление на 0.3.0 без кода доступа

Не создавайте новый сервис. Дождитесь deploy нового main и CI. В Environment проверьте REQUIRE_ACCESS_CODE=false; прежний APP_ACCESS_CODE можно удалить — при false он игнорируется. ANYMODEL_API_KEY и JWT_SECRET не меняйте и не отправляйте в чат. /v1/config должен показывать access_code_required:false, /health — version:0.3.0. Старый сервер с требованием кода несовместим с новым интерфейсом без кода: сначала дождитесь deploy сервера, затем проверьте новый APK.

Регистрация устройства/JWT происходит автоматически. Это **не авторизация конкретного человека**: человек, узнавший URL, может зарегистрировать новое устройство и тратить общий бюджет. Сохраняются IP/дневные/глобальные лимиты в памяти процесса; они сбрасываются при рестарте. Установите жёсткий бюджет/оповещения в AnyModel, если кабинет это поддерживает. Для широкого распространения нужны полноценная авторизация, постоянные квоты и edge-защита. Секрет в APK не является безопасной заменой.

Перед обновлением экспортируйте JSON из старого приложения. Пока стабильная подпись не настроена, разные debug-сборки могут не устанавливаться поверх друг друга. Не удаляйте приложение без проверенной копии: 0.3.0 умеет импортировать JSON старого формата v2 с подтверждением и слиянием по ID. Локальный профиль/согласие на новом устройстве задаются заново.

После установки: Профиль → Напоминания и поддержка → задайте сон/пробуждение, включите нужные каналы и сохраните. Разрешите уведомления; точное время Android разрешается отдельной кнопкой. 08:00–22:00 с интервалом 5 ч означает 08:00, 13:00, 18:00 каждый день. ОС может задерживать доставку; для строгой ночной тишины используйте также «Не беспокоить». На реальном телефоне проверьте заблокированный экран и перезагрузку.

## Постоянная подпись APK

Actions теперь требует четыре ANDROID_* Secrets и публичный SHA-256 сертификата в Variable ANDROID_SIGNING_CERT_SHA256. Без настройки сборка останавливается, случайной debug-подписи нет. Ключ создаётся один раз на ПК владельца. Пошаговая настройка, резервная копия ключа и переход со старой debug-установки — [RELEASE.md](RELEASE.md). Новый ключ не может обновить старый APK с другим сертификатом: сначала экспортируйте JSON. После перехода следующие сборки используют один ключ и возрастающий versionCode.
