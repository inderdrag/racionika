# AnyModel + Render: сайт и ИИ по одной ссылке

В render.yaml настроен **один Web Service**, который раздаёт собранный сайт и API. Не нужно отдельно создавать Static Site, задавать адрес API в браузере или держать компьютер включённым. Сервис в аккаунте Render здесь ещё не создан, живые запросы с ключом пользователя не выполнялись.

## 1. Подготовить AnyModel

В кабинете AnyModel получите API-ключ и проверьте баланс. Сохраните ключ приватно. Откройте каталог моделей: нужна модель, которая принимает изображения и возвращает текст (vision / imageToText), а не генератор картинок. Возьмите **точный API ID**, включая префикс провайдера, если он есть. Доступность и стоимость зависят от маршрута и аккаунта; не подставляйте названия моделей из старой инструкции Anthropic.

Для первого запуска можно использовать одну vision-модель: её ID будет одинаковым в MODEL_FAST и MODEL_ACCURATE. Это не делает два режима двумя разными моделями — различается только размер отправляемого фото.

Официальные сведения: https://anymodel.org/api-docs.md . Каталог API: GET https://anymodel.org/v1/models и GET /v1/models/image-to-text с авторизацией. Эти GET-запросы не выполняются браузером Рационики: ключ нельзя раскрывать клиенту.

## 2. Создать сервис через Blueprint

1. Войдите в https://dashboard.render.com/.
2. Выберите New → Blueprint. Подключите GitHub и разрешите доступ к приватному inderdrag/racionika.
3. Выберите репозиторий, ветку main и файл render.yaml. Если Render предлагает имя Blueprint — можно указать racionika.
4. Введите запрашиваемые значения:

| Переменная       | Значение                                                          |
| ---------------- | ----------------------------------------------------------------- |
| ANYMODEL_API_KEY | Ваш ключ AnyModel, только в защищённое поле Render                |
| APP_ACCESS_CODE  | Придуманный отдельный код доступа к Рационике; не пароль аккаунта |
| MODEL_FAST       | Точный API ID vision-модели из каталога AnyModel                  |
| MODEL_ACCURATE   | Такой же ID для начала, либо другой совместимой vision-модели     |

JWT_SECRET генерируется Blueprint автоматически. AI_PROVIDER=anymodel, SERVE_WEB=true, NODE_ENV=production и MOCK_AI=false уже заданы. Ключ Anthropic/OpenAI/Gemini не нужен. VITE_API_BASE_URL для этого сайта оставьте **незаданным**: запросы идут на тот же домен.

5. Проверьте выбранный тариф и регион перед созданием. В файле указан Free, но реальные условия и доступность определяет Render.
6. Создайте Blueprint/сервис и дождитесь успешной сборки и статуса Live. Если вы уже создавали старый racionika-api, не считайте его автоматически обновлённым: в текущем Blueprint имя racionika. Избегайте случайного создания второго оплачиваемого сервиса; можно обновить существующий вручную по следующему разделу.

## Альтернатива: уже создан Web Service

Root Directory оставьте пустой (корень репозитория), Branch=main, Runtime=Node.

Build Command:

```sh
npm ci --include=dev && npm run build
```

Start Command:

```sh
npm run start -w @racionika/server
```

Health Check Path: /health. В Environment задайте все переменные из Blueprint. JWT_SECRET при ручной настройке создайте как случайную строку минимум 32 символа; не используйте код доступа вместо него. NODE_VERSION=24.22.1. PORT не задавайте вручную: его предоставит Render. После изменения Environment выполните сохранение с повторным deploy.

Auto Deploy в Blueprint — checksPass: последующие deploy ждут GitHub CI. Если автоматический deploy не начался, проверьте Actions и настройки доступа к GitHub; не считайте отсутствие deploy успешной публикацией.

## 3. Открыть приложение

Render покажет **реальный URL вашего сервиса** вида https://имя.onrender.com. Не используйте этот пример как готовый адрес.

- Откройте /health: ожидается status:ok.
- Откройте /v1/config: ожидается mode:real и provider:anymodel. Это подтверждает конфигурацию, но не валидность ключа/баланса/моделей.
- Откройте корень сайта: должен появиться дневник, а не JSON.
- Добавить еду → описание → код APP_ACCESS_CODE → согласие → Определить КБЖУ.
- Начните с простого описания с известной массой. После успешного ответа проверьте фото и наставника. Первый настоящий запрос может списать токены AnyModel.

Один URL открывается на ПК и телефоне; установка Node на ПК больше не нужна. Однако дневник и чат всё ещё хранятся локально в браузере: разные устройства/браузеры не синхронизируются. Очистка данных сайта удаляет локальные записи.

## Если ошибка

- Сборка падает: проверьте корень репозитория, Build Command и GitHub Actions. Не присылайте логи с секретами.
- Сервер падает при старте: проверьте ключ, обе модели, JWT_SECRET и APP_ACCESS_CODE.
- «ИИ временно недоступен»: проверьте баланс, активность ключа, точные model ID и поддержку Chat Completions + изображений выбранным маршрутом. mode:real сам по себе этого не проверяет.
- На / показан 404: SERVE_WEB=true и сборка npm run build (не только server).
- Видите старое демо: проверьте URL и /v1/config, обновите страницу. В production MOCK_AI запрещён.
- Бесплатный сервер может просыпаться не сразу. Не отправляйте много повторов подряд: уже начатый запрос мог оплачиваться.

Это конфигурация личного теста. Квоты пока в памяти одного процесса и сбрасываются при перезапуске/засыпании. Перед публичным выпуском нужны постоянные счётчики и отдельный жёсткий бюджет у провайдера (SERVER.md). Не передавайте APP_ACCESS_CODE посторонним.
