# Render: только будущий деплой каркаса

Сервис на Render ещё не создан. render.yaml предназначен для /health; он не включает ИИ.

1. Создайте Render-аккаунт и подключите GitHub с доступом только к нужному приватному репозиторию.
2. New → Blueprint → inderdrag/racionika → main. Проверьте plan free и region Frankfurt. Blueprint запускает только backend.
3. Дождитесь сборки и проверьте выданный Render URL + /health. Не подставляйте вымышленный домен.
4. Автодеплой настроен `autoDeployTrigger: checksPass`, поддерживаемым Render параметром. Если CI ещё не виден, разберитесь со статусами перед релизом; первоначальный деплой проверьте отдельно.

Секреты вводить пока не нужно: ИИ-маршрутов нет. Когда будет готова фаза 3, в Render Environment потребуются ключ провайдера, JWT_SECRET и при необходимости APP_ACCESS_CODE; в Blueprint они должны быть sync:false. Они НЕ должны оказаться в клиентском .env, APK или GitHub Secrets.

JWT_SECRET впоследствии можно сгенерировать локально: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`. Результат — секрет, не публикуйте его в чате/логах/репозитории.

До реального подключения ИИ: проверить актуальные модели/цены/лимиты и возможность жёсткого денежного ограничения у конкретного провайдера. Не считать email budget alerts жёсткой отсечкой. Серверные счётчики в памяти не гарантируют потолок расходов.

Переменные VITE_API_BASE_URL используются текущим клиентом только для health. Переменная GitHub API_BASE_URL и её инъекция в APK workflow появятся в фазе 9. MAINTENANCE_MODE сейчас не реализован — не считайте его аварийным выключателем этой сборки.

Параметры сверены: https://render.com/docs/blueprint-spec . Актуальные условия free-tier и сон сервиса нужно проверить перед деплоем; платные ресурсы автоматически не создаются.
