# Статус 0.2.1

Целевой продукт — только Android APK. Render публикует API, не сайт. AnyModel подключается серверным ключом; в APK ключа нет.

## Есть в коде

Фото/описание → серверная валидация ответа → состав → локальный расчёт КБЖУ → редактирование массы → сохранение/повторное открытие. Дневник, вода, даты, ручной резервный ввод, JSON-экспорт, кеш, согласие, лимиты, наставник с локальным чатом и сводкой дня. Dexie v2 сохраняет старые ручные записи.

В 0.2.1 результат фото и текста упрощён: продукты, масса, ккал компонентов, общий вес и калории, сохранение. БЖУ не удалены из расчёта/хранения, только скрыты с этого экрана. Автодобавки видны компонентами, известная масса добавок входит в общий вес. Неизвестная масса соуса не выдумывается.

Android Actions собирает тестовый debug APK; после успешной сборки отдельная задача создаёт черновик Release с APK. Публикация вручную. Постоянная release-подпись ещё не настроена.

## Подтверждение и ограничения

Render /health и /v1/config проверены: ok, real/anymodel. Пользователь сообщил об успешной APK-сборке и распознавании по фото. Это не независимая проверка точности КБЖУ или установки новой версии 0.2.1. Новый APK должен быть собран из текущего main.

Данные локальны, между устройствами не синхронизируются. Импорт пока отсутствует. Разные debug-подписи могут мешать обновлению поверх установленной сборки: не удалять приложение без экспорта данных.

Не сделаны онбординг/личные цели/BMR/TDEE, проверенная база 400–600 продуктов, вес/графики, напоминания, импорт/CSV-отчёты, SSE и недельные разборы, постоянные квоты, dev-панель и стабильная подпись. Полная очередь и критерии — ROADMAP.md. Это не финальная реализация всего исходного ТЗ.
