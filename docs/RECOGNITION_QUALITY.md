# Контроль распознавания: первый набор

## Что изменено

- Все фото одного запроса считаются ракурсами одной порции. Одинаковые загруженные
  фотографии удаляются из списка до запроса. Это не распознавание одинаковых блюд
  на разных снимках: такую неоднозначность должна разрешать модель/пользователь.
- Фото сохраняются для запроса до 1600 px; в fast отправляется до 1280 px,
  в accurate — до 1600 px. Прежнее уменьшение fast до 768 px убрано, чтобы
  меньше терять читаемость этикеток. Ограничение 1,5 МБ на JPEG сохранено.
- Приоритет — явная масса пользователя, читаемая этикетка и сырой/готовый вид.
  Масса упаковки не означает съеденную массу. 100 мл не равны 100 г без плотности.
- Составное блюдо и его уже включённые компоненты нельзя складывать одновременно.
  Соус учитывается либо внутри готового блюда, либо отдельной подтверждённой
  порцией; его жир не становится ещё и дополнительным маслом.
- Новые ответы не содержат угаданных скрытых добавок. Явно указанное масло/соус
  остаются обычными ингредиентами и учитываются **один раз**.
- Точный повтор (нормализованное имя + те же граммы + те же четыре КБЖУ) и масса
  вне диапазона вызывают одну попытку исправления на сервере. После второй
  неудачи возвращается ошибка, не сомнительный результат. Повторные запросы
  учитываются в бюджете. Синонимы и пересечение рецептур этот алгоритм НЕ умеет
  надёжно определять: продукты не удаляются автоматически по похожести имени.
- На экране можно удалить лишний продукт и исправить массу. Изменённая вручную
  масса получает точный диапазон; исключение через 0 г сохранено.
- «Уточнить состав» свёрнуто по умолчанию. В нём — вопросы/предупреждения и
  повторный запрос с подсказкой; фотографии исходного запроса используются снова.
  Для старой записи без исходных фото доступны ручные правки, не фиктивный
  повторный анализ фотографии, которой больше нет.
- Калории ИИ/этикетки больше **не переписываются автоматически** формулой 4/4/9.
  Несовпадение даёт предложение сверить данные. Клетчатка, полиолы, алкоголь и
  специальные коэффициенты могут объяснять различия. Это не доказательство
  корректности любой цифры ИИ. Ручной запасной ввод сохранил прежние правила.
- Ключ кеша распознавания обновлён до revision 3: старые результаты не подменяют
  новый разбор. Уже сохранённый дневник не меняется задним числом.

## Что является контрольным набором сейчас

`fixtures/recognition/reference-cases.json` содержит **16 расчётных примеров**:
сырой/готовый рис, курица, сухие/готовые овсянка и макароны, яйца, миндаль,
банан с йогуртом, явное масло, соус и цельный продукт с учебной этикеткой.

**Это заданные массы, не измеренные нами на весах порции.** Набор не содержит
реальных фотографий или утверждений о проведённой фотопроверке.

Для USDA сохранены FDC ID и выпуск SR Legacy April 2018; значения совпадают с
локальным каталогом. Три учебные этикетки помечены `synthetic_label`, не выданы
за данные реальных брендов. Итоги предварительно вычислены отдельно в десятичной
арифметике; автотесты сверяют пересчёт, источник и сохранение энергии этикетки.

## Оценщик сохранённых ответов — без сети

Формат: `{ "mode": "recorded", "predictions": [{ "id": "rice-cooked", "analysis": ... }] }`.
`analysis` — полный ответ по контракту MealAnalysis; экспорт личного дневника
не является этим форматом. Не включайте ключи, токены, фото или личные сведения.

```bash
node --import tsx scripts/recognition/evaluate.ts \
  --predictions fixtures/recognition/predictions.example.json \
  --output /tmp/recognition-report.json
```

Пример специально помечен **fixture** и покрывает только 1 из 16 случаев.
Нулевое отклонение на нём проверяет оценщик, а не доказывает точность ИИ.

Отчёт показывает покрытие, отсутствующие/лишние ингредиенты, повторы, ошибку
массы, ккал и БЖУ (в том числе медиану и 90-й перцентиль массы/ккал), а также возвращённые угаданные добавки. Пропущенные примеры
не считаются успешными. Для неоднозначных названий используется строгое
сопоставление с `aliases`: допустимые синонимы добавляются после ручной проверки
вида продукта. Не разрешайте одним alias путать сырой и приготовленный продукт.
Калории считаются из ингредиентов без угаданных добавок, как в новом приложении.

## Реальный платный текстовый прогон — только вручную

Сборщик не запускается автоматически в CI и не получает ключ AnyModel.
Он обращается к уже настроенному серверу приложения. На компьютере нужен
Node 24 и установленный проект (`npm ci`).

```bash
# Linux/macOS; URL — ваш сервер Render, не AnyModel.
export RECOGNITION_BASE_URL=https://racionika.onrender.com
node scripts/recognition/collect.mjs --run-paid --output /tmp/recognition-live.json
node --import tsx scripts/recognition/evaluate.ts \
  --predictions /tmp/recognition-live.json --output /tmp/recognition-report.json
```

PowerShell:

```powershell
$env:RECOGNITION_BASE_URL="https://racionika.onrender.com"
node scripts/recognition/collect.mjs --run-paid --output "$HOME\recognition-live.json"
node --import tsx scripts/recognition/evaluate.ts --predictions "$HOME\recognition-live.json" --output "$HOME\recognition-report.json"
```

Если сервер закрыт кодом, задайте `RECOGNITION_ACCESS_CODE` приватно в окружении.
Не присылайте его в чат и не коммитьте. Флаг `--accurate` выбирает точный режим.

Сборщик отправляет **только 16 текстов из выбранного набора**, выдерживает паузу
7 секунд, останавливается при ошибке/квоте, сохраняет частичные результаты без
токена. Ответы демо не принимаются. Для 16 текстов возможно до 32 вызовов модели с учётом одной попытки исправления
каждого ответа. Расход зависит от модели и тарифа AnyModel;
мы этот платный прогон не выполняли. Измерение реальных фото он не заменяет.

## Как завершить проверку на взвешенных порциях и этикетках

Нужен отдельный набор реальных снимков, например 12–20 порций:

1. Взвесить съедобную часть без посуды; для составного блюда записать массы
   ингредиентов и выход после приготовления. Сырой и готовый вес не смешивать.
2. Записать масло/соус отдельно: сколько фактически попало в съеденную порцию,
   а не всё налитое на сковороду. Остаток/неизвестную долю отметить неизвестной.
3. Снять порцию сверху/сбоку и читаемую этикетку при наличии. Все ракурсы одной
   порции имеют один ID. Не фотографировать лица, чеки или личные данные.
4. Зафиксировать реальные КБЖУ с этикетки/рецепта и источник. Если выход, масса
   соуса или единица неизвестны — не выдавать такой случай за точный эталон.
5. Сначала сохранить эталон, затем получить ответы ИИ по фото и отдельно по
   тексту. Не менять эталон, чтобы подогнать его под ответ модели.
6. Сравнить до/после на одном наборе и тех же моделях, отдельно для fast/accurate,
   фото/текста, ингредиентов и порций. Вести число отказов/уточнений и не считать
   пропущенные результаты нулевой ошибкой.

Ориентир для первого контрольного прогона, не обещание точности: в случаях с
заданной массой/читаемой этикеткой — без повторов и потери указанных граммов,
расхождение пересчёта в пределах округления этикетки. Фото без масштаба могут
иметь существенную ошибку массы: отдельно публикуйте медиану/90-й перцентиль
ошибки, не скрывайте выбросы средним и не называйте оценку точным взвешиванием.

Реальные фотографии/этикетки ещё не предоставлены. Поэтому нельзя утверждать,
что модель стала точнее на X% или что завершена проверка взвешенных порций.
