# Решения и допущения

- 2026-10-24: рабочее название «Рационика» / Racionika. Android applicationId: `com.inderdrag.racionika`, репозиторий `inderdrag/racionika`, будущее имя сервиса Render `racionika-api`. Ник взят из владельца созданного GitHub-репозитория, а не угадан по почте.
- Репозиторий приватный. Лицензия исходного кода по умолчанию MIT; это не делает репозиторий публичным.
- Выполнение идёт по проверяемым этапам. Пустые экраны не имитируют ИИ. Первичная поставка — фундамент, не завершение всего ТЗ.
- Capacitor 8.5.3 выбран по npm registry. Плагин `@aparajita/capacitor-secure-storage` 8.0.1 явно поддерживает Capacitor 8. На Android его работа ещё не проверена на устройстве.
- Node 24.22.1 фиксируется в .nvmrc/CI/Render. Android-сборка требует JDK 21 (подтверждено исходниками установленного Capacitor), SDK 36, min SDK 24; среда здесь не содержит Android SDK/adb. JDK 25 среды не считается проверенной заменой JDK 21.
- Входящие пользовательские данные — только данные, никогда не инструкции системному промпту. До реализации защиты ИИ-маршруты не открываются.
- Текущая схема Dexie v1 минимальна и содержит только foodEntries/waterLogs; расширять её миграциями, без потери текущих записей.
- Без настроенного профиля не показываем выдуманную норму и процент выполнения. Значок-кольцо сейчас декоративный, а не шкала выполнения цели.
- Веб-токены будут только sessionStorage, native — Keystore через secure-storage. Токены пока не создаются и не экспортируются.
- Напоминания web работают только при открытой вкладке и не равнозначны фоновым Android-уведомлениям. Политика точных будильников и reboot-тесты отложены до фазы 6.
- Certificate pinning не используем: у хостинга ротируются сертификаты; оставляем системную проверку TLS и запрещаем cleartext.
- Gradle wrapper JAR хранится в репозитории как `.jar.base64`, потому что доступный GitHub MCP передаёт текстовые файлы. `postinstall` восстанавливает оригинал с проверкой SHA-256, без загрузки произвольного бинарника. Это только упаковка, не замена wrapper.
- Нельзя обещать жёсткий денежный лимит у любого провайдера: до production нужно проверить конкретные настройки провайдера, их применимость и задержки учёта. Сброс счётчиков в памяти после рестарта не является надёжным финансовым барьером.
- Не подставляем вымышленные `claude-haiku-5-5` / `claude-sonnet-5-5` из примера ТЗ. Модели и API будут проверены по документации при реализации провайдеров; сейчас провайдеров нет.
- Перед production необходимы отдельные исправления: доверенный Render proxy/IP, распределённые лимиты при масштабировании, стабильный контроль расходов, medical safety review. Текущий базовый rate limit не равен защите фазы 3.
