# База продуктов

## Использование

Дневник → Добавить еду → База продуктов. По умолчанию открыта база на телефоне:
**505 продуктов и вариантов приготовления**, 13 категорий. Поиск по русским и
исходным английским названиям, фильтры категории и вида. Для каждого варианта
свои КБЖУ на 100 г: сырая крупа не подменяется готовой кашей.

Выберите карточку, приём пищи и массу. Калории и БЖУ порции рассчитываются
локально. Фото и распознавание по тексту остаются отдельной функцией ИИ:
значения ИИ не объявляются автоматически проверенными по этой базе.

## Происхождение и точность

Источник: U.S. Department of Agriculture, Agricultural Research Service,
FoodData Central, **SR Legacy, final release April 2018**.

- https://fdc.nal.usda.gov/download-datasets
- https://fdc.nal.usda.gov/data-documentation
- https://fdc.nal.usda.gov/

Это фиксированная историческая выборка стандартных продуктов, не свежая база
российских торговых марок. Состав продуктов и рецептов может отличаться.
USDA объединяет данные анализов, расчётов и литературы; это не обещание
лабораторной проверки конкретной порции пользователя.

«Проверка» здесь — сверка всех 505 ID, исходных описаний, четырёх нутриентов,
единиц измерения и контрольных сумм с официальным набором. Русские названия —
локализованные обозначения; оригинал доступен в «Источник: USDA» вместе с ID,
выпуском и ссылкой на карточку. Сырой и готовый продукт используют разные
записи источника; коэффициенты приготовления не выдумываются.

Исходные калории сохраняются без принудительной замены на 4/4/9: для клетчатки,
специальных факторов Atwater и ряда продуктов такая замена искажает справочник.

### Воспроизводимая сверка

URL и SHA-256 архива/CSV: `scripts/catalog/manifest.json`.
Выборка и русские названия: `scripts/catalog/selection.json`.

1. Скачайте архив по `datasetUrl` из manifest.
2. Проверьте `datasetSha256` и распакуйте архив в отдельную папку.
3. Запустите:

```sh
python scripts/catalog/verify-usda.py /path/to/FoodData_Central_sr_legacy_food_csv_2018-04
```

Скрипт проверяет контрольные суммы CSV, ID нутриентов и единицы, затем сравнивает
все КБЖУ и исходные описания с поставляемым JSON. Флаг `--write` воспроизводит
JSON из того же проверенного набора, не обновляет выпуск автоматически.
После записи выполните Prettier для JSON.

Нутриенты: 1008 Energy (KCAL), 1003 Protein (G), 1004 Total lipid/fat (G),
1005 Carbohydrate, by difference (G). Значения относятся к 100 г продукта.
Отсутствующие значения не заполняются нулями.

## Внешний справочник

Вкладка «В интернете» использует **Open Food Facts**, не AnyModel. Запрос
выполняется только по кнопке, не по каждому введённому символу.

- Текст: `https://search.openfoodfacts.org/search` (официальный Search-a-licious).
- Штрихкод: `https://world.openfoodfacts.org/api/v2/product/{code}.json`.
- Из текстовой выдачи используются только названия/ID. При выборе отдельно
  загружается полная карточка продукта, чтобы проверить единицу и полноту КБЖУ.
  Запрос передаёт `q` и `page_size`: повторяющиеся `fields`/`langs` текущий
  публичный endpoint обрабатывает неоднозначно.
- Для локального просмотра готовой сборки CSP разрешает подключения только к
  двум указанным доменам и своему серверу. API-only Render не раздаёт интерфейс.
- Поиск отправляет только запрос/штрихкод напрямую в Open Food Facts. Профиль,
  дневник, ключ ИИ и токен приложения туда не отправляются.
- User-Agent: `Racionika/0.3.0 (https://github.com/inderdrag)` в нативных запросах.
- Не чаще одного текстового запроса в 7 секунд и карточки в 4,5 секунды;
  ограниченный кэш 30 запросов на час в памяти, без фонового массового скачивания.
- Таймаут интерфейса 15 секунд, отмена при закрытии, обработка 429/503/не-JSON.
  Нативный транспорт может завершить отменённый запрос позже; его результат не
  применяется. Офлайн-база остаётся доступной при ошибке внешнего сервиса.
- Неполные/невозможные КБЖУ и значения на порцию не принимаются. кДж переводятся
  в ккал только при явно указанном `energy-kj_100g`.

Данные Open Food Facts внесены пользователями: они не получают метку проверенных
USDA. Перед сохранением требуется сверить упаковку и подтвердить, что значения
на **100 г**, не 100 мл. Без плотности приложение не конвертирует миллилитры в
граммы. Автоматического сканера штрихкода камерой пока нет: код вводится текстом.

Документация:

- https://openfoodfacts.github.io/openfoodfacts-server/api/
- https://openfoodfacts.github.io/search-a-licious/users/ref-openapi/

  заполните форму использования API, рекомендованную Open Food Facts.

## Совместимость данных

Опциональное поле `catalogSource` хранит провайдера, ID, исходное описание и
выпуск. Новая таблица и миграция БД не нужны. Старые записи/копии JSON работают.
Источник сохраняется в избранном, при копировании и экспорте/импорте.
Изменение только массы сохраняет справочные значения и источник; ручная правка
названия или КБЖУ снимает атрибуцию и переводит запись в ручной ввод.

## Проверки

Unit: схема всей базы, число/уникальность карточек, сырой/готовый рис и гречка,
масштабирование порций, источники, поиск/фильтры, совместимость JSON, внешний
парсер, отсутствие нулей вместо пропусков, кДж, ограничения частоты, таймаут,
отмена и проверка полной карточки при выборе результата.

E2E: офлайн, граммовка, приём пищи, перезапуск, правка порции/КБЖУ, экспорт/
импорт и избранное, внешний поиск по кнопке, проверка упаковки, ошибка внешнего
сервиса, узкий экран. Сетевые E2E используют фикстуры, а не нагружают публичный API.
Физическую работу клавиатуры/источников и HTTP на Android проверьте новым APK.
