# Цель калорий и прогресс

## Как пользоваться

Профиль → Изменить данные профиля → Расчёт калорий → Своя цель калорий → Моя цель, ккал в день → Рассчитать мой план → Сохранить профиль.

«Автоматически по профилю» возвращает расчёт по исходным параметрам. Переключение не удаляет дневник.

Для ручной цели ниже автоматической перед сохранением нужна галочка «Понимаю, что выбрал цель ниже расчётной». При новом расчёте подтверждение сбрасывается. Для цели не ниже автоматической дополнительной галочки нет. Галочка не означает консультацию со специалистом и не отменяет проверок.

Нижние пороги приложения — 1300 ккал для женского профиля и 1500 для мужского. Индивидуальный минимум может быть выше из-за ограничения дефицита. Это не рекомендации по калорийности и не гарантия индивидуальной безопасности. Старые сохранённые профили с нормой ниже нового порога читаются без потери данных, но не используются для автоматического плана: показывается необходимость пересмотра цели.

## Поведение

- Ручная цель хранится в необязательном поле `customCalories`. Старые профили читаются без миграции; отсутствие поля сохраняет прежний автоматический расчёт.
- Белки учитывают массу тела, направление цели и калорийность; жиры — долю энергии, углеводы — остаток. Поэтому отдельные значения могут не расти линейно при каждом изменении калорий. Округлённые БЖУ дают выбранную энергию с небольшой погрешностью округления.
- Кольцо заполняется по отношению съеденных калорий к цели, от 0 до 100%. При превышении остаётся полным, а превышение показано числом. Удаление/редактирование блюда, смена даты или цели обновляют шкалу. У БЖУ также есть шкалы съеденного относительно цели.
- Наставник получает выбранную цель, БЖУ, текущие итоги дня и источник цели (`custom` / `automatic`). Полноценный автоматический составитель меню этим изменением не добавляется; советы ИИ остаются оценочными.
- В ручном режиме калории определяют расчётный темп и срок; отдельное пожелание по темпу не переопределяет выбранную калорийность. При отсутствии дефицита приложение не прогнозирует похудение.
- Экстремальные цели не поддерживаются. Сохранены ограничения по возрасту, особым состояниям, низкому ИМТ и слишком низкому расходу. Ручной ввод не обходит ограничения дефицита: учитываются нижняя граница, не более 25% расчётного расхода и ограничение темпа (не более 1% массы и 1 кг в неделю). Избыточный профицит также ограничен. Это защитные ограничения приложения, не гарантия индивидуальной медицинской безопасности.
- Выбор похудения на 8 кг в неделю и соответствующая экстремальная диета не добавлены.

## Проверка

- Модульные тесты: ручная цель, БЖУ/энергия, старый профиль, границы ввода, недопустимые состояния, расчёт срока без обещания результата.
- UI: сохранение после перезапуска, возврат к автоматическому расчёту, передача цели наставнику, круг 0/50/100%, превышение и удаление блюда, отказ слишком низкой цели.
- Изолированные UI-тесты используют фиктивный токен только при замоканном ответе наставника и не меняют рабочие лимиты сервера.
- Светлая/тёмная темы проверены на 390/360 px. Цели БЖУ вынесены на отдельную строку, чтобы трёхзначные значения не ломали вёрстку.
- Физический Android, реальные уведомления и реальный ответ AnyModel в этой среде не проверялись. Подпись APK и workflow не менялись.

### Проверка подтверждения цели

- 135 модульных тестов и 4 проверки Android URL прошли.
- Playwright: 44/44 в исходной и собранной версии; подтверждение требуется только для цели ниже автоматической, сбрасывается после нового расчёта и не позволяет пропустить проверки профиля.
- Пороги 1300/1500 проверены отдельно, включая сохранение старого профиля без сброса данных.
- Визуально проверены состояния до/после подтверждения в светлой и тёмной теме на 390/360 px. Кнопки изменения параметров и отмены разделены.
- ESLint, TypeScript и форматирование проходят. Android-ресурсы собраны для Render API и синхронизированы Capacitor; установка на физическом Android в этой среде не проверялась.
