# Постоянная подпись APK и обновления

Workflow **Android APK** теперь собирает **app-release.apk** с постоянным PKCS12-ключом. После успешной проверки APK прикрепляется к **черновику** GitHub Release; автоматической публикации нет. Ключ создаётся один раз на ПК владельца, не в каждом запуске Actions.

**Код подготовлен, но это не означает, что секреты уже настроены или новый APK собран.** Без обязательных Secrets и отпечатка workflow останавливается, а не подменяет постоянный ключ случайной debug-подписью.

## Важное ограничение перехода со старого APK

Android разрешает обновление только с совместимым сертификатом, тем же applicationId и не меньшим versionCode. У предыдущих debug-сборок ключ создавался на временном runner и мог отличаться. Если исходный ключ старого установленного APK не сохранён, новый постоянный ключ **не позволит обновить именно эту старую установку поверх**. Сертификат из APK не даёт приватного ключа, обойти это ограничение нельзя.

До первого перехода: экспортируйте JSON из старого приложения, сохраните копию вне телефона и проверьте, что файл не пустой. Сначала попробуйте обычное обновление. Если Android сообщает о несовместимой подписи, не удаляйте старое приложение до сохранения копии. После переустановки новой версии воссоздайте локальный профиль и импортируйте копию: Профиль → Импортировать JSON → проверка → подтверждение. Профиль, согласие и уведомления автоматически не импортируются.

**После этого все будущие APK с тем же постоянным ключом смогут обновляться без удаления приложения.** Потеря/замена ключа нарушает эту возможность. Новая подпись сама по себе не является Google Play-публикацией или гарантией качества приложения.

## Однократная настройка на Windows

### 1. Установить инструменты

Нужны GitHub CLI и JDK 21 (Android Studio и Android SDK на ПК для этого не нужны). Если инструменты уже есть, повторная установка не требуется. В PowerShell:

```powershell
winget install --id GitHub.cli -e
winget install --id Microsoft.OpenJDK.21 -e
```

Закройте и откройте PowerShell заново. Проверьте `gh --version` и `keytool -help`. Если keytool не найден, проверьте JAVA_HOME/PATH или перезапустите сеанс Windows.

### 2. Войти в GitHub под владельцем репозитория

```powershell
gh auth login --hostname github.com --web --git-protocol https
```

Пройдите вход в своём браузере под **inderdrag**, с доступом к приватному racionika и управлению Actions Secrets/Variables. Ключи и пароли не нужно присылать в чат. Не запускайте настройку на чужом/общедоступном ПК.

### 3. Скачать помощник из своего приватного репозитория

Откройте обычную папку вне репозитория, например домашнюю. Команды не выводят секреты:

```powershell
$code = gh api "repos/inderdrag/racionika/contents/scripts/setup-android-signing.ps1?ref=main" --jq .content
if ($LASTEXITCODE -ne 0) { throw "Не удалось скачать помощник" }
[IO.File]::WriteAllBytes("$HOME\setup-android-signing.ps1", [Convert]::FromBase64String(($code -join "")))
notepad "$HOME\setup-android-signing.ps1"
```

Просмотрите скрипт из своего репозитория. Затем запустите:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\setup-android-signing.ps1"
```

ExecutionPolicy меняется только для этого процесса, не для всей системы. Если политикой организации выполнение запрещено, не обходите её — используйте согласованный способ настройки.

### 4. Что спросит помощник

- Придумайте пароль ключа **от 16 символов** — латинские буквы, цифры и знаки, без пробелов, сохраните его в менеджере паролей. Ввод скрыт; при создании нужно повторить.
- Скрипт создаёт RSA-3072 PKCS12 с alias **racionika** и сроком сертификата 10000 дней, либо повторно использует существующий локальный файл, **не перегенерируя его**.
- Показывает публичный SHA-256 сертификата и просит напечатать **YES** перед загрузкой в GitHub.
- Через защищённый stdin GitHub CLI загружает четыре repository Actions Secrets:
  - ANDROID_KEYSTORE_BASE64
  - ANDROID_KEYSTORE_PASSWORD
  - ANDROID_KEY_ALIAS
  - ANDROID_KEY_PASSWORD
- Записывает публичный отпечаток в repository Actions Variable **ANDROID_SIGNING_CERT_SHA256**. Пароль keystore и ключа одинаковы для этого PKCS12, это ожидаемо.

Ключ остаётся на ПК: **%USERPROFILE%\.racionika-signing\racionika-release.p12**. Каталог ограничивается ACL текущего пользователя. Сделайте отдельную зашифрованную резервную копию файла на надёжном носителе; пароль храните отдельно. GitHub Secrets не заменяют резервную копию: прочитать их обратно через интерфейс нельзя. Base64 — кодировка, не шифрование; не отправляйте её в чат/логи/Issues.

Если GitHub уже содержит ключ, но локального файла нет, помощник останавливается. Восстановите **тот же** файл из копии, не создавайте новый. При несовпадении отпечатка также остановится. Для иной папки копии можно передать `-KeyDirectory "D:\Private\Racionika"`.

## Сборка после настройки

1. GitHub → Actions → **Android APK** → Run workflow → **main**.
2. api_base_url: **https://racionika.onrender.com**, без /v1 и без ключей.
3. Дождитесь успеха обеих задач: apk и Create draft release.
4. Releases → новый черновик → **app-release.apk**. Резервно — Artifacts → **racionika-release-apk** (ZIP нужно распаковать).
5. Установите APK. Не удаляйте старое приложение «на всякий случай»; сначала прочитайте ограничение перехода выше.

В Actions ключ восстанавливается только во временный каталог runner с правами 600, сертификат проверяется по закреплённому SHA-256, пароли передаются окружением. После сборки временные файлы удаляются даже при ошибке. Готовый APK повторно проверяется apksigner, проверяются versionCode и отсутствие debuggable. Приватный ключ в APK, artifact или репозиторий не включается. Давать права на изменение workflow стоит только доверенным людям.

## Нумерация обновлений

applicationId остаётся **com.inderdrag.racionika**. Для CI versionCode = **1000 + GITHUB_RUN_NUMBER**, если не задана repository Variable ANDROID_VERSION_CODE_BASE. Повтор того же run использует тот же код; новый запуск получает следующий. Локальное значение по умолчанию — 5. Установленную CI-сборку с кодом 1000+ нельзя заменить локальной сборкой с меньшим кодом, даже с тем же ключом.

Не удаляйте/не пересоздавайте workflow и не уменьшайте базу. Если GitHub сбросил номер workflow, задайте ANDROID_VERSION_CODE_BASE так, чтобы следующий versionCode был **выше любого уже установленного**. Это ручная аварийная настройка, не повод менять ключ. versionName 0.3.0 — отображаемая версия, не счётчик совместимости обновлений.

## Проверки и границы

Локально проверяются входы подписи, отсутствие fallback, SHA-256 и возрастание versionCode. Одноразовый тестовый PKCS12 проверяет keytool/восстановление/отказ при другом сертификате; это **не ключ приложения**. Bash-синтаксис шагов workflow проверяется отдельно. В sandbox нет Android SDK: Gradle assembleRelease, apksigner готового APK, Windows ACL и установка требуют реального запуска Actions и проверки на ПК/телефоне. Успешное обновление подтверждается установкой двух последовательных release-сборок с сохранением дневника.

## Название и описание в Releases

Новые черновики получают понятный заголовок, например:
**«Рационика 0.3.0 — 20 000 продуктов и удобный дневник»**.
Версия берётся из `app/package.json`, текст заголовка и список изменений —
из `docs/RELEASE_NOTES.md` **того же коммита, из которого собран APK**.

Перед следующим выпуском обновите `docs/RELEASE_NOTES.md`: первая строка —
короткий заголовок с `#`, ниже — описание реальных изменений для пользователя.
Номер версии меняется в `app/package.json` по принятому в проекте порядку.
Не пишите в этом файле ключи, пароли или другие секреты.

`node scripts/release-notes.mjs` формирует имя `racionika-VERSION.apk`,
заголовок и Markdown-описание с установкой и сведениями о сборке.
Номер запуска, попытка и SHA спрятаны в раскрываемый блок описания,
а не занимают название релиза. Уникальные теги запусков, проверка подписи,
возрастающий versionCode и ручная публикация черновика сохранены.

Изменение применяется к **новым сборкам**. Старые релизы не переименовываются
автоматически: их APK могут не содержать перечисленных новых функций.
