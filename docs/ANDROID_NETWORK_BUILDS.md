# Устойчивость APK-сборки к сбоям загрузки Kotlin

Ошибка `Could not download kotlin-compiler-embeddable-2.0.21.jar` с HTTP 504
происходит при получении зависимости Gradle, до компиляции приложения.

## Исправление

1. `scripts/gradle-repositories.init.gradle` добавляет официальный Google-hosted
   mirror Maven Central первым источником **только для групп Kotlin** в buildscript
   каждого проекта, включая `capacitor-local-notifications`. Существующие Google
   Maven/Maven Central остаются на месте. Версии зависимостей не подменяются;
   произвольные JAR с GitHub вручную не скачиваются.
2. `scripts/android-build.mjs` запускает Gradle с этим init-script и делает до
   трёх попыток при распознанных временных сетевых сбоях (504/503/429, таймаут,
   сброс соединения) с паузами 10 и 20 секунд. Компиляция, неверный пароль,
   отсутствие ключей и HTTP 401/404 не маскируются повторами. Если все попытки
   неудачны, workflow завершается с ошибкой, а не публикует старый APK.
3. Android APK workflow кэширует только `~/.gradle/caches/modules-2` и Gradle
   wrapper. Временный keystore, signing-переменные и проектный configuration-cache
   в этот кэш не входят. Постоянный сертификат, versionCode и проверки подписи,
   non-debuggable release и публикация в черновик сохранены.
4. Корневая команда `apk:release` и тесты release/signing сохранены; новые тесты
   retry-механизма включены в обычный `npm test`.

## Проверки

- Моделируются 504 → успех, три последовательных сетевых сбоя и отсутствие
  повторов при ошибке компиляции/подписи; проверяются release-задача и init-script.
- Отдельный реальный Gradle-проект разрешает именно
  `kotlin-compiler-embeddable:2.0.21` через зеркало: Gradle подтверждает совпадение
  checksum с доступным локальным артефактом, размер JAR — 58 272 093 байта.
  Дополнительно весь JAR скачан через Google mirror без Gradle-кэша; SHA-1 совпал
  с ранее разрешённым Maven-артефактом.
- Полная release-сборка проверяется локальным временным сертификатом, не ключом
  пользователя. Такой APK не является обновлением для установленного приложения.

Кэш и повторы не гарантируют доступность внешних сервисов при полном сетевом
отказе. Исправление необходимо запускать новым workflow на актуальной `main`,
а не повтором старого run со старой версией скриптов.

Итог: форматирование, lint, 250 Vitest + 21 Node-тест — пройдены. Новый
`npm run apk:release` завершился успешно; предварительно удалён старый APK,
проверены сертификат временного ключа, новый versionCode и отсутствие
`application-debuggable`. Рабочий ключ пользователя не использовался.
