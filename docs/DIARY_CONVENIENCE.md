# Удобство дневника

## Меры порций

`app/src/core/catalog/portions.json`: 285 мер для конкретных ID USDA из официального SR Legacy 2018-04, таблица `food_portion.csv`.

Источник архива: https://fdc.nal.usda.gov/download-datasets/ ; карточка продукта: `https://fdc.nal.usda.gov/food-details/<fdc_id>/nutrients`.

Каждая строка: `[fdc_id, русская подпись, gram_weight, food_portion.id, modifier]`. Использованы только записи `amount=1` и точные модификаторы `cup`, `tbsp`, `tsp`; `large` — только для яиц. Порции относятся только к исходным 505 локализованным продуктам: вес не переносится на похожий товар, другой бренд или сырой/готовый вид. Объём жидкости не переводится в граммы по предположению о плотности. Числа совпадают с исходной таблицей. Проверка: `python3 scripts/catalog/verify-portions.py /path/to/food_portion.csv`.

US cup явно помечен, ложки названы столовой/чайной. При ручной корректировке меняется текущая форма, не справочник. Записи и JSON-копии продолжают хранить граммы, миграция базы не нужна.

## Поиск и история

Статический индекс на 20 000 записей, кэш 32 запросов. При нулевом результате — ограниченный словарный fallback с одним исправлением/перестановкой соседних букв; короткие слова, штрихкоды и числа не исправляются. «творк» — явный бытовой алиас. Это подсказка поиска, не замена выбранного продукта. Нутриенты и источник не меняются.

История — последние 1000 записей устройства, без демо и составных блюд без точного источника. Ранжирование: знакомые продукты, дата последнего использования, частота, исходный порядок. Порция предлагается по идентичному source.provider/source.id, только явным нажатием. История удаляется вместе с записями, не отправляется в сеть для поиска.

## Добавление серии

Прямое добавление: каждый продукт сохраняется отдельно в выбранную категорию и дату; закрытие окна не отменяет уже сохранённое. Внутри конструктора — только компоненты черновика, сохранение всего блюда отдельно. Кнопка сохранения заблокирована во время записи, категория сохраняется при возврате к поиску.

## Календарь

Локальные даты, сдвиг через календарный день, не фиксированные 24 часа (переход летнего времени). Отметки: индекс `foodEntries.day`, реактивно обновляются при импорте, добавлении и удалении. Вода сама по себе не отмечает день как заполненный дневник еды. Границы 1900–9999.

## Android

ACK/SNOOZE — явные immutable PendingIntent к неэкспортируемому ReminderReceiver. Проверяются generation, id и конкретное occurrence последнего отображённого уведомления; повторное нажатие игнорируется. ACK не обращается к дневнику/БЖУ. Snooze хранится в существующей цепочке SharedPreferences и восстанавливается после перезагрузки; тихие часы, дни недели и следующий слот имеют приоритет. «Записать еду» открывает MainActivity, плагин принимает также intent холодного запуска. После force-stop Android потребуется открыть приложение.

На реальном телефоне проверить: действия при закрытом приложении; ACK отменяет +30/+60, но не следующий приём; snooze +30 и восстановление после перезагрузки; граница сна и выходной; холодный запуск «Записать еду»; отсутствие новых калорий после ACK. Полная доставка зависит от разрешений/ограничений производителя, веб-тесты не заменяют эти проверки.
