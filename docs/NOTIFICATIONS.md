# Android: уведомления, расписания и повторы

## Пользовательские настройки

Профиль → Напоминания и поддержка:

- дни недели (Пн–Вс, по календарной дате и местному времени телефона);
- еда через интервал либо до 8 конкретных часов;
- вода через выбранный интервал;
- поддержка в выбранное время;
- сон/пробуждение: уведомления, в том числе повторы, не отправляются во время сна;
- «Повторять, если еда не записана»;
- «Не напоминать после выполнения нормы еды или воды».

Старые настройки мигрируют без потери выбранных интервалов. Новые поля получают значения по умолчанию. Повтор еды и учёт нормы можно отключить независимо. Изменения применяются только после «Сохранить напоминания». Пустые дни, еда во время сна и слишком тесные часы отклоняются; одинаковые часы не дублируются.

## Цепочка еды

Пример: основной приём запланирован на 08:00.

1. В 08:00 — обычное напоминание.
2. Если еда не отмечена, через 30 минут после фактической доставки — повтор.
3. Если записи всё ещё нет, ещё через 30 минут — заключительное уведомление «Приём пищи не отмечен». В тексте: «Вы пропустили запланированный приём пищи. Если уже поели — отметьте это в дневнике». Четвёртого повтора нет.

Отсутствие записи не доказывает, что человек не ел, поэтому приложение не записывает «пропуск» как медицинский/пищевой факт и не требует компенсировать его едой.

Запись еды отменяет оставшиеся повторы и убирает актуальное уведомление. Учитывается время еды либо время создания записи; запись сегодня с явно более ранним временем еды тоже останавливает повтор. Еда за 30 минут до основного напоминания также считается отмеченной. Демо, повреждённая еда, будущие записи и копия на прошлую дату не отмечают сегодняшний приём.

Повторы не переносятся на сон, не переходят в следующий основной приём и не накапливаются после перезагрузки. При часовом интервале приоритет у следующего основного приёма, а не у заключительного повтора предыдущего. Изменение расписания отменяет старые цепочки. Удаление уже записанной еды не воссоздаёт ранее отменённую цепочку.

## Учёт нормы

Нативная часть получает из дневника только итоги калорий/воды за последние 3 календарные даты, времена записей и текущие цели. Названия еды, заметки, фото, чат и имя туда не копируются. Демоеда исключена. Обновления отправляются при изменении дневника/профиля и при возвращении в приложение.

Если настройка учёта нормы включена, выполненная калорийная цель останавливает уведомления о еде, а выполненная водная — уведомления о воде. Цели независимы. На следующий календарный день старые итоги не используются; неизвестная/нулевая цель не считается выполненной. Мотивация от норм не зависит.

Это не рекомендация прекращать есть при достижении числа калорий или пить ради числа миллилитров; цели — пользовательские ориентиры приложения.

## Нативный механизм

`RacionikaReminders` — локальный Capacitor-плагин, зарегистрированный в MainActivity. AlarmManager и BroadcastReceiver работают без Activity, WebView, JS-таймеров и интернета.

В приватных SharedPreferences сохраняются настройки, незавершённые цепочки и минимальные итоги. Backup приложения отключён. При выключении всех напоминаний очищается и нативная копия итогов; последующая синхронизация не сохраняет её, пока расписание выключено. Новое расписание получает свежие итоги вместе с настройками.

Старые периодические Capacitor-уведомления с ID 10000–39999 удаляются при миграции, чтобы не получить два расписания.

На каждый основной слот создаётся ближайший одноразовый будильник. После срабатывания планируется следующий допустимый день. Повтор создаётся только после фактического показа предыдущего уведомления и перед показом снова проверяет дневник, норму, дни и сон. Изменение конфигурации меняет поколение задач, чтобы старые доставки не сработали по новой конфигурации.

Расписание восстанавливается после BOOT_COMPLETED (после разблокировки), MY_PACKAGE_REPLACED, смены времени/часового пояса и предоставления разрешения на точные будильники. На старте приложения выполняется сверка. Просроченные цепочки после перезагрузки не догоняются пачкой. Уже показанные части не запускаются заново из JS.

Обычная доставка использует `setExactAndAllowWhileIdle`, если доступно разрешение. Иначе — `setAndAllowWhileIdle`, без самовольного открытия системных экранов и без обхода энергосбережения. «Точное время уведомлений» открывается только по действию пользователя.

## Что Android не позволяет обещать

- После «Остановить принудительно» Android блокирует будильники до следующего ручного запуска приложения.
- Отзыв разрешений, выключенный канал, запрет фоновой работы, OEM-ограничения и энергосбережение могут задерживать или блокировать доставку.
- Точное время требует соответствующего разрешения; даже allow-while-idle не является обещанием доставки секунда в секунду.
- Очень устаревшие срабатывания и повторы после начала следующего приёма отбрасываются, а не создают лавину уведомлений.

## Проверка владельцем на реальном телефоне

Сначала собрать новый APK и установить поверх старого. Открыть приложение хотя бы один раз и сохранить расписание. В Профиле → Напоминания → Проверка на телефоне есть тест через минуту; он показывает также состояние точных будильников, энергосбережения и ограничения фоновой работы. Это проверка доставки, не ускоренная трёхэтапная цепочка еды. Явно запрошенный тест может прийти и в тихие часы.

| Сценарий                 | Действия                                                                 | Ожидается                                                                            |
| ------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Закрытое приложение      | Тестовое уведомление → убрать приложение из недавних → ждать             | Тест без открытого интерфейса; задержка возможна по политике ОС                      |
| Цепочка еды              | Поставить ближайший час, не вводить еду; закрыть приложение              | Основное, через 30 минут повтор, ещё через 30 заключительное; без четвёртого         |
| Отмена после записи      | После основного уведомления записать реальную еду                        | Повтор и заключительное не приходят                                                  |
| Уже поел                 | Записать еду незадолго до времени напоминания                            | Основное/повторы этого слота не приходят                                             |
| Сон                      | Установить сон между основным и повтором                                 | Ночных повторов нет                                                                  |
| Дни недели               | Выключить текущий/следующий день                                         | В эти календарные даты уведомлений нет                                               |
| Вода                     | Выполнить норму воды, калории не выполнять                               | Вода молчит до следующего дня, еда остаётся                                          |
| Еда                      | Выполнить цель калорий, воду не выполнять                                | Еда/повторы молчат до следующего дня, вода остаётся                                  |
| Перезагрузка             | Сохранить часы → перезагрузить → разблокировать, не запускать приложение | Следующие основные часы восстановлены; старые не приходят пачкой                     |
| Энергосбережение         | Повторить основной слот и тест с выключенным экраном и энергосбережением | Фактическую задержку зафиксировать; не обещать точность без проверки модели телефона |
| Обновление APK           | Установить поверх, не удаляя                                             | Настройки/дневник сохранены, расписание восстановлено                                |
| Принудительная остановка | Force stop → ждать → открыть вручную                                     | До открытия доставку не обещаем; после открытия расписание восстановлено             |

Автотесты UI и Java-правил не заменяют эту проверку установленного APK на конкретном устройстве. Реальное выключение телефона, Doze и ограничения производителя нельзя подтвердить браузерным тестом.
