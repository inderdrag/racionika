# Changelog

## Дополнение AnyModel + Render — 2026-10-24

- Отдельный адаптер AnyModel Chat Completions, фото image_url и usage.
- Сайт и API одним сервисом Render: SERVE_WEB, same-origin API без ключей в клиенте.
- Blueprint и подробная инструкция AnyModel/Render; обязательный код доступа для публичного сайта.
- Браузерная проверка именно собранного сайта, без Vite.

## 0.2.0 — 2026-10-24

- Автоматический разбор описания и до3фото через серверные Anthropic/OpenAI/Gemini адаптеры.
- Состав,граммовки,уточнения,lookup ингредиента,автодобавки и локальный пересчёт КБЖУ.
- Наставник со сводкой дня,локальной историей и согласием на передачу.
- JWT,код доступа,строгие схемы,лимиты,таймауты,ограниченный повтор неверного JSON.
- Явный dev:demo без платных вызовов,кеш оценок и миграция Dexie v2.
- Документация ПК/реального ключа/Render и расширенные проверки.
- Реальные провайдеры,Render deploy и Android APK пока не проверены.

## 0.1.0 — 2026-10-24

- Начальный monorepo, shared-контракты, health-only сервер, Android-исходники.
- Прототип ручных записей и воды, локальное сохранение и экспорт.
- Unit/inject/E2E проверки и базовый CI.
- ИИ и APK release ещё отсутствуют.

## Уточнение Android-only — 2026-10-24

- Render переключён на API без раздачи сайта; добавлена сборка build:server.
- Ручной GitHub Actions workflow Android APK принимает только публичный HTTPS URL сервера и публикует тестовый debug APK как artifact при успешной сборке.
- Перед сборкой APK проверяется адрес API, ключ AnyModel остаётся на Render. Удалённая Android-сборка ещё не подтверждена.

## Исправление Android SDK setup — 2026-10-24

- setup-android@v3 получает packages: platform-tools вместо дефолтного tools platform-tools. Устаревший tools вызвал сбой первого удалённого запуска до сборки приложения.
- Вывод текста лицензий сокращён; отдельный шаг установки Platform 36 / Build Tools 36.0.0 сохранён. Успех повторной APK-сборки пока не подтверждён.

## APK в черновиках GitHub Releases — 2026-10-24

- После успешной задачи apk отдельная задача draft-release скачивает тот же artifact и создаёт черновик релиза с app-debug.apk. Автоматическая публикация отсутствует.
- Право contents:write дано только задаче черновика; используется штатный GITHUB_TOKEN, новый персональный ключ не нужен. Уникальный тег содержит run ID и attempt; target — точный коммит сборки.
- Существующие успешные сборки автоматически не переносятся: нужен новый запуск обновлённого workflow.
