# Рационика / Racionika 0.3.0

Локальный дневник питания с автоматической оценкой КБЖУ по **описанию и 1–3 фото**. React + TypeScript + Dexie, Android-оболочка Capacitor, отдельный Fastify ИИ-прокси.

> Техническая версия, не весь продукт из исходного ТЗ. Автоанализ реализован, но настоящие запросы требуют ключа провайдера на сервере. Без ключа доступен **явно помеченный фиксированный демопример**, не распознавание. Пользователь подтвердил работу распознавания по фото; независимая проверка точности не выполнялась. Фото не заменяет весы и этикетку. Render API работает, пользователь сообщил об успешной APK-сборке; текущую 0.3.0 нужно собрать заново.

## Что работает

- Описание еды или фотографии → состав, граммовки и оценка калорий.
- КБЖУ порции считает код. Результат: продукты, масса, калории компонентов и итог. Правки граммов пересчитываются локально, без нового платного запроса.
- Сохранение и редактирование разбора, вода с личной целью и своим объёмом, даты, ручной резервный ввод, JSON-экспорт и подтверждаемый импорт старых копий без дублей.
- Первый вход: локальный профиль и цель, BMR/TDEE, калорийный коридор, БЖУ, вода; безопасные ограничения и редактирование параметров. Это не облачная регистрация.
- Настраиваемые повторяющиеся локальные Android-уведомления: еда/вода, часы сна и мотивация из подготовленных фраз; отдельные системные разрешения.
- Вес и история, светлая/тёмная/системная тема, единое управление согласием.
- ИИ-наставник со сводкой выбранного дня и локальной историей.
- Серверные адаптеры AnyModel/Anthropic/OpenAI/Gemini, автоматический JWT устройства без ввода кода, лимиты, таймауты, Zod-проверка. Удаление кода снижает защиту от посторонних: нужен бюджет у провайдера, см. SERVER.md.
- Одно явное согласие при первом входе, сохранённое до отзыва в Профиле. Фото сжимаются и очищаются от EXIF; приложение не сохраняет исходные фото. Локальный кеш оценок: 24 часа, до 50 записей.

## Основной вариант: Android APK + Render + AnyModel

Продукт — отдельное Android-приложение, **без опубликованной веб-версии**. Render запускает только ИИ API (SERVE_WEB=false); интерфейс находится внутри APK. Ключ AnyModel остаётся на Render. Инструкция от настройки сервера до установки: [docs/RENDER.md](docs/RENDER.md).

После создания сервера запустите GitHub Actions → **Android APK** → Run workflow и укажите публичный HTTPS URL сервера в api_base_url. При успешной сборке следующий шаг автоматически создаёт **черновик GitHub Release** с прикреплённым app-debug.apk; публикация только вручную. Резервная копия остаётся в Artifacts → racionika-debug-apk. Это подготовленный workflow для тестовой debug-сборки, не уже собранный файл и не подписанный релиз для магазина. Android SDK здесь отсутствует; пользователь сообщил об успешной удалённой APK-сборке после исправления SDK setup. Автоматический черновик релиза проверяется следующим запуском.

## Только разработка: проверка интерфейса на ПК (Windows)

Нужны **Node.js 24 LTS** и Git. Android Studio для браузера не нужна. В PowerShell:

```powershell
git clone https://github.com/inderdrag/racionika.git
cd racionika
npm.cmd ci
npm.cmd run dev:demo
```

Если папка уже клонирована: откройте терминал в ней и выполните `git pull --ff-only`, затем `npm.cmd ci` и `npm.cmd run dev:demo`. Если Git сообщает о ваших изменениях — не удаляйте их принудительно.

Откройте **http://localhost:5173**. Демо проверяет интерфейс и расчёт на одном фиксированном блюде; оно не распознаёт произвольную еду. Остановка — Ctrl+C. На macOS/Linux используйте `npm` вместо `npm.cmd`.

## Локальная разработка: настоящее определение КБЖУ

1. Остановите демо. Скопируйте `server/.env.example` в `server/.env`.
2. Только в этом локальном файле задайте `ANYMODEL_API_KEY`, длинный `JWT_SECRET`; `REQUIRE_ACCESS_CODE=false`. Генератор секрета и альтернативные провайдеры — в [docs/DEV.md](docs/DEV.md).
3. Укажите `AI_PROVIDER=anymodel` и точные ID vision-моделей в `MODEL_FAST` и `MODEL_ACCURATE`. Оставьте `MOCK_AI=false`. Запустите `npm.cmd run dev`.
4. Откройте localhost:5173 → «Добавить еду» → описание или фото → «Определить КБЖУ». Единое согласие задаётся при первом входе или в Профиле; поля кода в APK нет. Настоящие запросы оплачиваются по тарифу провайдера.

**Ключ никогда не вставляется в код приложения, VITE-переменные или GitHub.** Для установленного приложения ключ хранит владелец сервера; каждый пользователь не должен заводить свой ключ.

## План и простой результат

Результат распознавания фото и текста: только состав, редактируемая масса, ккал компонентов и итог по весу/калориям. Настройки и технические пояснения не дублируются после анализа. Масло/сахар/соус не прячут калории от видимого состава.

Дальнейшие этапы и критерии готовности: [docs/ROADMAP.md](docs/ROADMAP.md).

## Ограничения

По фото нельзя гарантировать точные массу, рецепт и скрытое масло. ИИ-значения — оценка, не проверенная пищевая база. Для точного учёта используйте весы и этикетку через ручной ввод. Нельзя обещать медицинскую точность.

Квоты сервера пока в памяти одного процесса и сбрасываются при его перезапуске; для публичного сервиса нужен общий постоянный счётчик и дополнительный edge rate limit. Установите также жёсткий бюджет у ИИ-провайдера. См. [SERVER.md](docs/SERVER.md).

Ещё не готовы: онбординг и личные цели, локальная база 400–600 продуктов, графики прогресса, готовые напоминания, импорт, отчёты, Service Worker, подписанные релизы. Полный статус — [STATUS.md](docs/STATUS.md); проверки — [QA.md](docs/QA.md); развёртывание — [RENDER.md](docs/RENDER.md); исходное [ТЗ](docs/REQUIREMENTS.original.md).
